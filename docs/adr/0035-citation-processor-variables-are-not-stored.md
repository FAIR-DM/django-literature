# ADR 0035 — The variables a citation processor assigns are not stored

**Status:** accepted

## Context

CSL JSON 1.0.2 defines five variables that describe one citation in one document rather than the
reference being cited:

| Variable | What the specification says it is |
|---|---|
| `citation-number` | The reference's position in a bibliography, generated by the processor |
| `first-reference-note-number` | The note a reference was first cited in, assigned by the processor |
| `year-suffix` | The "a" in "Doe, 1999a", which separates two works in the same bibliography |
| `locator` | A cite-specific pinpointer, such as the page being cited, which must come with a label naming its type |
| `citation-label` | The label a label style shows in the text, such as "Ferr78", which the processor may assign from the item's metadata |

The CSL citation schema puts `locator` and its `label` on each entry of a citation's
`citationItems`, beside `prefix` and `suffix`. That is one row per time a work is cited. The item
schema carries `locator` with no `label`, so a locator stored on an item cannot say what it
counts. The other four are worked out by the processor every time it formats a document.

This package stores references. It formats no documents and records no citations. `Item` held a
column for each of the five, which no person could fill in or read meaning from (#147).

## Decision

The five columns are removed from `Item`, and migration `0004` drops them. CSL JSON import does not
keep these variables, and export does not write them.

The constitution's round-trip guarantee (Article IX and the quality bar) is narrowed to the
variables that describe a reference.

They are not moved into `custom`. CSL JSON defines `custom` for information that has no field of
its own, and these five have one. Keeping them there would keep values that still describe no
reference.

## Consequences

- A CSL JSON file that carries any of the five comes back from an import and an export without
  them. Everything else in the file comes back as before.
- Stored values are dropped with the columns. They are not bibliographic data, so Article V's
  data-migration path does not apply.
- They appear nowhere in the front end: not on the form, not on the reference page, not in the
  field groups.
- Citing references in a page or article, if it is ever built, needs a record per citation, linking
  a reference to the place that cites it. `locator` and its label would live on that record. The
  other four would still be worked out by a citation processor and never stored.
- `tests/test_ui/test_fieldgroups.py`'s ceiling on how many fields a journal article leads with
  measured against every field in the groups, which included these five although they were never on
  the form. It now states its bound as the count it was set at, fewer than 30 fields, half of the 60
  the groups then held. No type's assignment changed, and a journal article still leads with 28.
