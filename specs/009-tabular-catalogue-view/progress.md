- **2026-08-19 — design review.** One reviewer, three lenses, all three asking for changes. Two findings were genuinely blocking and both were verified in source before acting on them. The pagination component replaces the whole query string on every page link, so a chosen order is lost on turning the page and the sort-survives-pagination requirement could not be met as designed — the fix belongs in django-mvp, where the href is hard-coded, and this feature's dependency floor rises to the release carrying it. The credited-names cell was specified as a Python renderer emitting one link per contributor with no escaping mechanism named, over free text entered through write pages this feature deliberately leaves open; it becomes a template column, exactly as the issued cell already is. Five further findings taken: the issued cell needs its own prefetch or the constant-query-count guarantee fails, `Meta.order_by` named a column that does not exist and was silently doing nothing, the item-type renderer restated behaviour the library already provides, the issued column advertised a sort two stories before the annotation behind it landed, and the empty-value marker had no implementing task. Two research findings were amended: one confirmed a mechanism existed and read as though it had confirmed the default was right, the other confirmed markup survived without checking what it carried.

- **2026-08-19 — US-1 complete (T004–T013).** The catalogue is a table. `literature/ui/tables.py` gained `ItemTable`: the four plain columns (citation key, item type, container title, and title with its five-rung fallback chain and its route-built link, since `Item` has no `get_absolute_url()`), the credited-names column (`table_contributors.html`, author-role names falling back to editor-role, first three plus a translatable count of the rest, never touching the manager), and the issued column (`table_issued.html`, reusing `date_value.html` so the precision-and-range rule stays in one file). `ItemTableView` sits beside `ItemListView`, unchanged, and `literature/ui/urls.py` now routes `item-list` at the table; the card stays reachable as a routable class with no template copied out. Full suite (1542 tests), lint, format, types, `deptry` and the template guards all green.
  One deviation from `plan.md`'s D-2/D-3 pseudocode, both load-bearing: `ItemTable.Meta` declares no `model` — with one set and no `fields`, django-tables2 generates a column for every field `Item` carries, which is exactly the silent-column problem `fields` being left unset was meant to prevent, and column alignment infers correctly from the queryset regardless (`mvp/templatetags/mvp.py` reads `table.data.model`, not `Meta.model`). And the credited-names/issued columns select their values through `TemplateColumn.get_context_data()` on a small column subclass rather than a table-level `render_<name>` method: `render_<name>` on the table replaces the column's own template rendering outright (verified empirically), which would have defeated the whole point of routing the markup through a template for escaping. `get_context_data()` is the pattern django-tables2's own docs show for exactly this split.
  T009 (the view) and T010 (routing) could not be verified independently — the view has nothing to route to before T010, and T010 immediately breaks the card's own tests, which T011 re-points in the same change. Landed as one commit, per the task graph's own dependency note anticipating exactly this.
  `makemessages` could not be run in this environment (`msguniq`/GNU gettext tools not installed) — deferred to T028, which already owns the "makemessages clean" gate.

The one-line change referred to in the spec turned out to need more care than a literal one-line diff: `literature.ui.urls`'s bundled `include()` gives every route in the app one shared namespace, and registering a second `include()` under the same namespace to override just the list route breaks reversal for the *other* routes in that namespace (`literature:item-create` stopped resolving from within the card view — confirmed empirically, not assumed). The documented pattern instead swaps the one entry in the already-imported `literature.ui.urls` module before the single `include()` call reads it, which keeps every route in the one namespace it has always been in. `django_tables2` was added to the installation `INSTALLED_APPS` block, and the item-type sort note (FR-017) is stated where a reader looking at the table would be.
