{% extends "page_view.html" %} {% load i18n %} {% comment %} The report page (US-1, US-4, plan.md "The report" seam). Extends the plain page layout rather than form_view.html or list_view.html: this page is neither a form nor a queryset-backed list, and page_view.html's own page.content block is the one this app already leaves for a bare page (mvp/templates/page_view.html). Three states share this one template rather than three separate ones (US-4, decisions.md D16): - ``nothing_to_confirm`` — a confirmation naming a file that is no longer staged, or that this session never staged (FR-044). Carries no report at all: there is nothing to describe. - ``preview`` — the default path through a submission (FR-038). Reports exactly what a real import would, labelled as not having happened yet, with a control that carries it out (FR-039). - neither — an ordinary completed report, from a confirm or from the skip-preview path (FR-040). The report now carries the upload form itself, above the results (decisions.md D17), which is what removes the tension D11 recorded: FR-023's promise that the report page runs nothing again was the best available answer while the report was a dead end, and it no longer is — the preview is what makes running it again safe. Both views hand this template an ``import_form`` of its own, kept separate from ``form``: ``ItemImportView`` passes the submission it has just read, so the format the reader chose stays selected, and ``ItemImportConfirmView`` passes an unbound one, since its own ``ConfirmImportForm`` declares no field (decisions.md D16). Only the ``nothing_to_confirm`` state renders without it: there is no report there for it to sit above. {% endcomment %} {% block page.content %} {% if nothing_to_confirm %} {% blocktranslate %} There is nothing to confirm.
